aseri · for programs and people

API

Every forecast on this site, as files: nine daily series, a forecast of each from its newest data, the real values, and how past forecasts did. Static JSON, read-only, rebuilt each day at about 07:00 UTC.

Base URL https://exdsgift.github.io/aseri/api/v1/

Files

series.json
The catalog: each series' unit, horizon, newest data and forecast, source, licence and links, the model, the 21 quantile levels and the errata.
series/{series_id}/latest.json
The newest forecast, a copy of its dated file.
series/{series_id}/forecasts.json
Every forecast issued, oldest first, with its file.
series/{series_id}/forecasts/{reference_date}.json
One forecast. Written once, never changed.
series/{series_id}/actuals.json
The real values of the last 400 days, as known on its as_of day.
series/{series_id}/replay.json
The forecasts of the last 120 days at seven levels, rounded as this site writes them.
series/{series_id}/scores.json
The track record: live forecasts and the backtest apart, never combined.
scores.json
Every series' track record, as this site shows it.
openapi.json, schemas/{name}.schema.json
The contract: OpenAPI 3.1 and JSON Schema 2020-12.
licenses/{name}.txt
The full licence texts.
model-metadata/aseri-timestral209m_c1.yml
The model, in Hubverse model metadata. Its bands are calibrated per series on a two-year backtest: ADR 0001.

The series: gpr_daily, wiki_ww3_views, brent_spot, suez_transits, hormuz_transits, bab_el_mandeb_transits, taiwan_strait_transits, ua_air_raid_hours and ua_drones_downed_claimed.

A forecast

A forecast reads its series up to reference_date, its last observed day, and gives each step h of horizon a day, target_end_date: reference_date plus h days, or for brent_spot the h-th trading day after it. forecast_date is the UTC day of the run that made it. forecast_mode is live, or retrospective for one made after the fact, such as the 120-day backfill at launch; the live record counts live forecasts only.

quantiles holds an array per level, from "0.01" to "0.99", aligned with horizon. From "0.1" to "0.9" is the 8 in 10 range: the daily value should land inside it 8 days in 10, outside it about 2 in 10. It is not a high and a low. "0.5" splits the forecast in half.

fetch("https://exdsgift.github.io/aseri/api/v1/series/gpr_daily/latest.json")
  .then((response) => response.json())
  .then((forecast) => forecast.quantiles["0.9"])

Contract

openapi.json and the JSON Schemas are the contract, kept in the repository's api/ folder. Before each deploy the daily run checks every file against its schema, dates included, and that the files agree with each other and each step's day follows from its reference date. It holds each newest forecast to bounds drawn from its series' last 365 days. A file that fails stops the deploy.

v1 only grows: new fields, files, series and values. Ignore what you do not know. Anything else goes to /api/v2/, next to v1 for 6 months at least. A dated forecast never changes: a correction goes to errata in series.json, each with its date, series_id, reference_date and description, and the original stays published and scored. None so far.

Use

  • GET only, no query strings. Send no custom headers: GitHub Pages refuses the CORS preflight they cause.
  • Pages caches for 10 minutes, so poll once an hour at most. Right after a deploy series.json and latest.json can disagree for a moment: both carry forecast_date.
  • A missing file answers 404 with an HTML page: check the status before parsing.
  • Days are ISO 8601 dates with no time zone. Timestamps are UTC, to the second.
